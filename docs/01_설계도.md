# 설계도

본 문서는 라이브러리의 구조와 구성 요소, 그리고 요소 사이의 관계를 설명합니다. 처음 접하는 사람이 전체 그림을 파악하는 것을 목적으로 합니다.

## 1. 무엇을 하는 도구인가

한국 기업의 재무 실무에서 발생하는 검토 요청을 받아, 해당 분야의 법령과 기준에 비추어 사전 검토 산출물을 생성하는 도구입니다. 산출물은 담당자가 검토하기 위한 초안이며, 최종 결정과 외부 응대는 사람이 수행합니다.

## 2. 세 개의 층

```
                            ┌────────────────────────────────┐
        호출자  ──────────▶ │  오케스트레이터 (O1)           │
                            │  배정 · 통합 판단 · 위험 단계  │
                            └────────────────┬───────────────┘
                                             │
        ┌───────────────────┬────────────────┴──┬───────────────────┐
        ▼                   ▼                   ▼                   ▼
┌────────────────┐  ┌────────────────┐  ┌────────────────┐  ┌────────────────┐
│ 재무보고 분과  │  │ 외부규제 분과  │  │ 재무자문 분과  │  │ 법무연계 분과  │
├────────────────┤  ├────────────────┤  ├────────────────┤  ├────────────────┤
│ S1  회계       │  │ S3  세무       │  │ S6  자금       │  │ S8  법무       │
│ S2  외부감사   │  │ S4  공시       │  │ S7  부동산금융 │  │                │
│ S10 내부회계   │  │ S5  공정거래   │  │ S9  경영관리   │  │ 외부 자문 연계 │
└───────┬────────┘  └───────┬────────┘  └───────┬────────┘  └───────┬────────┘
        └───────────────────┴─────────┬─────────┴───────────────────┘
                                      │
                      ┌───────────────▼────────────────┐
                      │  공용 자산                     │
                      │  행동 규칙 · 오류 유형         │
                      │  산출물 서식                   │
                      └────────────────────────────────┘
```

**첫째 층은 오케스트레이터입니다.** 호출자의 요청을 받아 어느 분과가 담당할지 정하고, 여러 분과의 판단이 엇갈리는 지점을 통합합니다.

**둘째 층은 열 개의 분과 검토자입니다.** 각자 담당 법령과 기준을 토대로 검토하며, 다른 분과의 영역은 신호만 표시하고 결론을 내지 않습니다. 열 개를 한 줄로 나열하면 읽히지 않으므로 네 묶음으로 나누어 배치합니다. 나누는 기준은 담당 법령이 아니라 결론이 무엇에 잠기는가입니다.

| 묶음 | 분과 | 결론이 잠기는 곳 | 가장 강하게 걸리는 장치 |
|---|---|---|---|
| 재무보고 | S1 회계, S2 외부감사, S10 내부회계 | 회계기준, 감사기준, 외부감사법 | R7 교차 검토의 완전성 |
| 외부규제 | S3 세무, S4 자본시장·공시, S5 공정거래 | 법령 조항과 정량 임계치 | 미탐지 영점 원칙과 R3 위험 단계 |
| 재무자문 | S6 자금, S7 부동산금융, S9 경영관리·기획 | 조항이 아니라 §0 입력 가정 | R9 결정론 보증과 R10 정보 밀도 |
| 법무연계 | S8 법무 | 실체 판단을 보유하지 않고 경로만 보유 | R2 출력 의무의 금지 산출 형태 |

묶음은 읽기의 단위이며 배정의 단위가 아닙니다. 배정은 분과 단위로 수행하고 묶음 이름을 배정 결과에 적지 않습니다. 다만 오케스트레이터의 분과 구성 표와 공용 규칙의 분과별 표, 저장소 소개 문서의 분과 목록에는 같은 묶음과 같은 순서를 적용합니다. 세 곳의 순서가 같아야 처음 보는 사람이 하나의 지도를 얻습니다.

**셋째 층은 공용 자산입니다.** 모든 페르소나가 상속하는 행동 규칙과 오류 유형, 산출물 서식이 여기에 있습니다.

## 3. 공용 자산

| 파일 | 담는 내용 | 구성 |
|---|---|---|
| `shared/universal-rules.md` | 행동 규칙 | R1 정보 확보, R2 출력 의무, R3 위험 단계, R4 객관성, R5 공통 원칙, R6 자기 평가, R7 교차 검토, R8 외부 자료, R9 결정론 보증, R10 정보 밀도 |
| `shared/universal-anti-patterns.md` | 오류 유형 | AP1부터 AP21까지와 AP10′을 더한 스물두 개 항목 |
| `shared/output-templates.md` | 산출물 서식 | 머리글·바닥글·제3자 관점 검증·약점과 불확실성·외부 자료 확인·자기 평가와 형식별 구성 요건 |

정본은 저장소 최상위의 `shared/` 이며, 각 페르소나 폴더의 `shared/` 는 사본입니다. 사본을 두는 이유는 페르소나 폴더 하나만 배포해도 단독으로 작동하도록 하기 위함입니다.

## 4. 세 가지 설계 원칙

### 4.1 사람이 결정합니다

페르소나는 초안을 만들고 위험을 짚습니다. 결정과 외부 응대는 사람의 영역입니다. 이 경계를 넘는 산출은 오류로 분류합니다.

### 4.2 같은 입력에는 같은 결론이 나옵니다

모든 산출물은 §0에 입력 가정을 표로 기재하고, §0.1에 가정과 결론의 대응을 적으며, 본문의 결론마다 어느 가정에 잠겨 있는지 표시합니다. 이렇게 하면 같은 사안을 다시 검토해도 결론이 흔들리지 않고, 가정이 바뀔 때 어떤 결론이 갈리는지 즉시 파악할 수 있습니다.

### 4.3 분량은 사안의 크기에 비례합니다

산출물의 형식은 요약형, 표준형, 상세형 세 가지입니다. 페르소나가 사안의 영향도를 판단하여 형식을 권고하고 호출자가 선택합니다. 일상적인 검토에 법률 회신문 수준의 분량을 적용하지 않으며, 외부 자문 의뢰서에 요약 수준의 분량을 적용하지 않습니다.

## 5. 검토가 흘러가는 순서

1. 호출자가 요청을 입력합니다.
2. 오케스트레이터가 담당 분과를 정합니다. 여러 분과에 걸치면 연쇄로 배정합니다.
3. 담당 페르소나가 사안의 영향도를 판단하고 권장 형식을 제시합니다.
4. 호출자가 형식을 선택합니다. 형사 영역 신호가 감지되면 질의 없이 상세형으로 상향합니다.
5. 페르소나가 §0 입력 가정을 확정하고 본문을 작성합니다.
6. 여러 분과가 참여한 경우 오케스트레이터가 결론을 통합하고 정합성을 평가합니다.
7. 호출자가 검토하고 결정합니다. 사실관계가 추가되면 판번호를 올려 갱신합니다.

## 6. 확장 계획

분과를 나누는 기준은 토대입니다. 담당하는 법령과 기준이 다르면 분리하고, 같으면 하나의 페르소나 안에서 형식을 나눕니다.

남은 확장 대상은 운영 성격의 영역입니다. 경영 보고 자동화와 시스템 관리, 데이터 연계가 이에 해당하며, 사내 자료를 주기적으로 읽을 수 있는 기반이 갖추어진 뒤에 구축합니다. 기반 없이 먼저 만들면 호출해도 산출할 것이 없기 때문입니다.

판단 성격의 영역은 법령과 기준, 그리고 호출자가 제공하는 사실관계만으로 검토가 성립하므로 데이터 연계와 무관합니다. 자금, 부동산금융, 법무, 경영관리·기획, 내부회계를 본 판에서 구축한 근거가 여기에 있습니다.

법무 분과에는 후속 확장 지점이 하나 남아 있습니다. 계약서 개별 조항의 수정안 산출이며, 회사의 표준 계약 서식과 과거 분쟁 이력이 자산으로 갖추어진 뒤에 착수합니다.
