# 설계도

본 문서는 라이브러리의 구조와 구성 요소, 그리고 요소 사이의 관계를 설명합니다. 처음 접하는 사람이 전체 그림을 파악하는 것을 목적으로 합니다.

## 1. 무엇을 하는 도구인가

한국 기업의 재무 실무에서 발생하는 검토 요청을 받아, 해당 분야의 법령과 기준에 비추어 사전 검토 산출물을 생성하는 도구입니다. 산출물은 담당자가 검토하기 위한 초안이며, 최종 결정과 외부 응대는 사람이 수행합니다.

## 2. 세 개의 층

```
                    ┌──────────────────────────┐
   호출자  ───────▶ │  오케스트레이터 (O1)      │
                    │  배정 · 통합 판단          │
                    └────────────┬─────────────┘
                                 │
        ┌────────┬───────────────┼───────────────┬────────┐
        ▼        ▼               ▼               ▼        ▼
      ┌────┐  ┌────┐          ┌────┐          ┌────┐  ┌────┐
      │ S1 │  │ S2 │          │ S3 │          │ S4 │  │ S5 │
      │회계│  │외감│          │세무│          │공시│  │공정│
      └──┬─┘  └──┬─┘          └──┬─┘          └──┬─┘  └──┬─┘
         └───────┴───────────────┴───────────────┴───────┘
                                 │
                    ┌────────────▼─────────────┐
                    │  공용 자산                │
                    │  행동 규칙 · 오류 유형     │
                    │  산출물 서식              │
                    └──────────────────────────┘
```

**첫째 층은 오케스트레이터입니다.** 호출자의 요청을 받아 어느 분과가 담당할지 정하고, 여러 분과의 판단이 엇갈리는 지점을 통합합니다.

**둘째 층은 다섯 개의 분과 검토자입니다.** 각자 담당 법령과 기준을 토대로 검토하며, 다른 분과의 영역은 신호만 표시하고 결론을 내지 않습니다.

**셋째 층은 공용 자산입니다.** 여섯 개 페르소나가 모두 상속하는 행동 규칙과 오류 유형, 산출물 서식이 여기에 있습니다.

## 3. 공용 자산

| 파일 | 담는 내용 | 구성 |
|---|---|---|
| `shared/universal-rules.md` | 행동 규칙 | R1 정보 확보, R2 출력 의무, R3 위험 단계, R4 객관성, R5 공통 원칙, R6 자기 평가, R7 교차 검토, R8 외부 자료, R9 결정론 보증, R10 정보 밀도 |
| `shared/universal-anti-patterns.md` | 오류 유형 | AP1부터 AP17까지 열여덟 개 항목 |
| `shared/output-templates.md` | 산출물 서식 | 머리글·바닥글·제3자 관점 검증·약점과 불확실성·외부 자료 확인·자기 평가와 형식별 구성 요건 |

정본은 저장소 최상위의 `shared/` 이며, 각 페르소나 폴더의 `shared/` 는 사본입니다. 사본을 두는 이유는 페르소나 폴더 하나만 배포해도 단독으로 작동하도록 하기 위함입니다.

## 4. 세 가지 설계 원칙

### 4.1 사람이 결정합니다

페르소나는 초안을 만들고 위험을 짚습니다. 결정과 외부 응대는 사람의 영역입니다. 이 경계를 넘는 산출은 오류로 분류합니다.

### 4.2 같은 입력에는 같은 결론이 나옵니다

모든 산출물은 §0에 입력 가정을 표로 기재하고, §0.1에 가정과 결론의 대응을 적으며, 본문의 결론마다 어느 가정에 잠겨 있는지 표시합니다. 이렇게 하면 같은 사안을 다시 검토해도 결론이 흔들리지 않고, 가정이 바뀔 때 어떤 결론이 갈리는지 즉시 파악할 수 있습니다.

### 4.3 분량은 사안의 크기에 비례합니다

산출물의 형식은 요약형, 표준형, 상세형 세 가지입니다. 페르소나가 사안의 영향도를 판단하여 형식을 권고하고 호출자가 선택합니다. 일상적인 검토에 법률 회신문 수준의 분량을 적용하지 않으며, 외부 자문 의뢰서에 요약 수준의 분량을 적용하지 않습니다.

## 5. 검토가 흘러가는 순서

1. 호출자가 요청을 입력합니다.
2. 오케스트레이터가 담당 분과를 정합니다. 여러 분과에 걸치면 연쇄로 배정합니다.
3. 담당 페르소나가 사안의 영향도를 판단하고 권장 형식을 제시합니다.
4. 호출자가 형식을 선택합니다. 형사 영역 신호가 감지되면 질의 없이 상세형으로 상향합니다.
5. 페르소나가 §0 입력 가정을 확정하고 본문을 작성합니다.
6. 여러 분과가 참여한 경우 오케스트레이터가 결론을 통합하고 정합성을 평가합니다.
7. 호출자가 검토하고 결정합니다. 사실관계가 추가되면 판번호를 올려 갱신합니다.

## 6. 확장 계획

현재 구축된 분과는 검토 성격의 다섯 개입니다. 운영과 통합 성격의 분과인 FP&A 분석, 자금 운영, 경영 보고, 시스템 관리는 데이터 연계 기반이 갖추어진 뒤에 구축합니다. 기반 없이 먼저 만들면 실익이 없기 때문입니다.
