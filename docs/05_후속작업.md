# 후속 작업

본 문서는 남은 작업과 환경별 수행 절차를 정리합니다. 환경에 따라 가능한 일이 다르므로, 작업을 시작하기 전에 어느 환경에서 수행할지 먼저 확인합니다.

## 1. 환경별 가능 범위

| 작업 | Cowork | Claude Code | 사용자 직접 |
|---|:---:|:---:|:---:|
| 저장소 파일 읽기와 편집 | 가능 | 가능 | 가능 |
| 형상 관리 커밋과 태그 생성 | 가능 | 가능 | 가능 |
| 원격 저장소 반영 | 불가 | 가능 | 가능 |
| `~/.claude/skills/` 연결 관리 | 불가 | 가능 | 가능 |
| 연결되지 않은 폴더 접근 | 승인 필요 | 가능 | 가능 |
| 파일 삭제 | 승인 필요 | 가능 | 가능 |
| claude.ai 개인 스킬 등록 | 불가 | 불가 | 가능 |
| 대량 문서 개편 | 가능 | 가능 | 해당 없음 |

**원격 저장소 반영이 Cowork에서 불가한 이유.** Cowork의 셸은 사용자 컴퓨터와 분리된 가상 환경에서 실행되며, 연결된 폴더만 마운트합니다. 저장소 파일은 읽고 쓸 수 있으나 사용자 컴퓨터의 자격증명 저장소에는 접근하지 못하므로 인증이 필요한 원격 반영을 수행할 수 없습니다.

**연결 관리가 Cowork에서 불가한 이유.** `~/.claude/` 는 연결 대상 폴더 밖에 있으며, 도구가 접근을 차단하는 보호 영역입니다.

## 2. Claude Code에서 수행할 작업

본 절의 두 항목은 2026-09-09에 수행하여 완료하였습니다. 다만 명령은 한 번 쓰고 버리는 것이 아니라 세션을 새로 시작할 때마다 상태를 확인하는 절차이므로 그대로 둡니다.

### 2.1 원격 저장소 반영

```bash
cd ~/My_project/Claude_Project/k-finance-personas
git log --oneline -5
git status -sb
git push origin main --follow-tags
```

반영 후 태그가 원격에 존재하는지 확인합니다.

```bash
git ls-remote --tags origin
```

### 2.2 Claude Code 연결 확인

링크가 존재하는지가 아니라 어디를 가리키는지를 확인합니다. 링크가 살아 있으면서도 저장소 정본이 아닌 다른 사본을 가리키면 옛 판이 적재됩니다.

```bash
cd ~/My_project/Claude_Project/k-finance-personas
for p in orchestrator s1-accounting-reviewer s2-external-audit-responder \
         s3-tax-reviewer s4-capital-market-disclosure-reviewer s5-fair-trade-reviewer \
         s6-treasury-reviewer s7-real-estate-finance-reviewer s8-legal-issue-reviewer \
         s9-management-planning-reviewer s10-internal-accounting-control-reviewer; do
  t=$(readlink -f "$HOME/.claude/skills/$p" 2>/dev/null)
  [ "$t" = "$PWD/$p" ] && echo "$p 정상" || echo "$p 불일치 — $t"
done
```

한 건이라도 「불일치」가 나오면 다시 만듭니다.

```bash
cd ~/My_project/Claude_Project/k-finance-personas
for p in orchestrator s1-accounting-reviewer s2-external-audit-responder \
         s3-tax-reviewer s4-capital-market-disclosure-reviewer s5-fair-trade-reviewer \
         s6-treasury-reviewer s7-real-estate-finance-reviewer s8-legal-issue-reviewer \
         s9-management-planning-reviewer s10-internal-accounting-control-reviewer; do
  ln -sfn "$PWD/$p" "$HOME/.claude/skills/$p"
done
```

다시 만든 뒤 위 확인 명령을 한 번 더 실행하여 열한 종이 모두 「정상」으로 나오는지 봅니다.

## 3. 사용자가 직접 수행할 작업

### 3.1 claude.ai 개인 스킬 재등록

압축 파일을 먼저 생성합니다.

```bash
cd ~/My_project/Claude_Project/k-finance-personas
python3 docs/tools/build_packages.py
```

저장소 최상위에 페르소나별 압축 파일 열한 개가 생성됩니다. claude.ai의 설정에서 개인 스킬로 순차 등록하며, 새 판의 작동을 확인한 뒤 이전 판의 스킬을 삭제합니다.

## 4. 자료 확보 후 착수할 작업

두 건은 산출물 원본이 없어 착수할 수 없습니다. 2026-09-10 로컬 디스크 전체를 검색한 결과 휴지통에서도 발견되지 않았습니다. 원본은 claude.ai 세션에만 있는 것으로 보입니다.

| 작업 | 필요한 자료 |
|---|---|
| 두 개 산출물에 결정론 항목 소급 적용 | 임차인 인테리어 비용 보전 검토서, 거래 사실관계 통합 검토서 |
| 시험 기록의 잔여 지표 기입 | 위 두 산출물의 참여 분과, 교차 검토 범위, 외부 자료 확인 횟수 |

원본을 확보하면 `docs/02_시험기록.md` 제4절의 「미기록」 항목을 채웁니다.

## 5. 실무 사용 시 확인할 사항

새 판을 적용한 뒤 첫 실무 호출에서 다음을 확인합니다.

1. 페르소나가 사안의 영향도를 스스로 판단하는지 확인합니다.
2. 권장 형식을 제시하고 선택을 요청하는지 확인합니다.
3. 형사 영역 신호가 있는 사안에서 질의 없이 상세형으로 상향하는지 확인합니다.
4. 산출물의 문장이 서술 기준을 지키는지 확인합니다.

확인 결과는 `docs/02_시험기록.md`에 기록합니다.
