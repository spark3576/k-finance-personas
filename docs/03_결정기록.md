# 결정 기록

본 문서는 확정된 결정과 그 근거를 기록합니다. 같은 논의를 반복하지 않기 위한 자료이며, 새로운 제안을 검토하기 전에 확인합니다.

## 1. 구조에 관한 결정

| 번호 | 결정 | 근거 |
|---|---|---|
| D-01 | 공용 자산을 최상위 `shared/` 에 정본으로 두고 각 페르소나 폴더에 사본을 배치합니다 | 페르소나 폴더 하나만 배포해도 단독 실행이 가능해야 하기 때문입니다 |
| D-02 | 공시 영역을 오케스트레이터에서 분리하여 S4로 독립시켰습니다 | 정량 임계치를 세 가지 근거로 확인해야 하고, 누락 시 형사 처벌에 노출되기 때문입니다 |
| D-03 | 공정거래 영역을 오케스트레이터에서 분리하여 S5로 독립시켰습니다 | 신호 표시만으로는 정량 결론을 낼 수 없고, 형사 처벌 영역이기 때문입니다 |
| D-04 | 운영·통합 분과 네 개의 구축을 후순위로 두었습니다 | 데이터 연계 기반이 없는 상태에서는 구축의 실익이 없기 때문입니다 |
| D-17 | 시각 서식의 정본을 본 저장소에 두지 않고 사내 브랜드 스타일 가이드를 따르며, 본 저장소에는 기본값과 연결 규칙만 둡니다 | 색상값과 치수를 두 곳에 두면 어느 한쪽이 갱신될 때 어긋나기 때문입니다. 정본은 브랜드 담당이 관리하는 자산입니다 |

## 2. 규칙에 관한 결정

| 번호 | 결정 | 근거 |
|---|---|---|
| D-05 | 호출자가 제공하지 않은 고유명사의 사용을 중대 오류로 분류합니다 | 초기 시험에서 회사명을 추론하여 단정하는 결함이 반복되었기 때문입니다 |
| D-06 | 제3자 관점 검증과 외부 자료 확인을 거래의 복잡도와 무관하게 필수로 정하였습니다 | 단순한 거래에서 항목이 임의로 생략되는 사례가 확인되었기 때문입니다 |
| D-07 | 결론을 입력 가정에 잠그는 결정론 보증 체계를 도입하였습니다 | 같은 사안을 다시 검토했을 때 결론이 달라질 수 있는 구조적 위험이 있었기 때문입니다 |
| D-08 | 산출물 형식을 세 가지로 나누고 표준형을 기본값으로 정하였습니다 | 종전 기본값이 사실상 상세형이어서 일상 검토에 과도한 분량이 적용되었기 때문입니다 |
| D-09 | 오류 유형의 식별자를 재번호하지 않고 유지합니다 | 과거 산출물과 시험 기록이 기존 식별자를 참조하고 있기 때문입니다 |
| D-18 | 형식과 판본을 서로 다른 층으로 정의하고, 형식이 판본 구성을 결정하도록 하였습니다 | 요약형·표준형·상세형과 원본·요약·핵심이라는 두 개의 삼분법이 같은 층에 놓이면 실무에서 어느 쪽을 고르는지 혼동되기 때문입니다 |
| D-19 | 결론을 싣는 판본에는 그 결론이 잠긴 가정을 반드시 함께 싣도록 하였습니다 | 판본은 따로 떼어 읽히므로, 가정이 빠진 판본만 읽은 사람은 잠기지 않은 결론을 받게 되어 R9 결정론 보증이 깨지기 때문입니다 |

## 5. 기록 규칙

- 새로운 결정은 해당 절에 번호를 이어 추가합니다.
- 종전 결정을 뒤집는 경우 원래 항목을 지우지 않고 「D-XX를 대체함」이라고 명시한 새 항목을 추가합니다.
- 결정의 근거는 반드시 함께 적습니다. 근거 없는 결정은 다음 세션에서 다시 논의 대상이 됩니다.
